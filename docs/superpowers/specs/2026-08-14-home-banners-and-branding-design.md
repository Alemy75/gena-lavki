# Тексты баннеров главной и айдентика через админку

## Задача

Сейчас тексты обоих баннеров главной захардкожены в компонентах, а логотипа нет
вовсе. Владелец сайта не может поменять ни заголовок, ни описание, ни favicon без
правки кода и деплоя. Нужно вынести это в админку.

Редактируемое:

- **Главный баннер** ([components/hero-banner.tsx](../../../components/hero-banner.tsx)) — заголовок (h1) и абзац.
- **Баннер доставки** ([components/delivery-banner.tsx](../../../components/delivery-banner.tsx)) — заголовок (h2), абзац, список пунктов с галочками.
- **Логотип** — квадратная картинка слева от названия сайта в шапке.
- **Favicon** — иконка сайта.

Вне объёма (осознанно): подписи кнопок («Связаться с нами», «Подробнее о
доставке →»), картинка лавки в главном баннере и иконка грузовика в баннере
доставки остаются в коде.

## Решение

Фича делится на две независимые части с разными владельцами данных.

### Часть 1. Тексты баннеров — модель `HomeContent`

Новая singleton-модель (`@@map("home_content")`, `id = 1`), отдельная от
`SiteSettings`: та отвечает за реквизиты компании, а это — контент главной.
Смешивать телефон и текст баннера в одной таблице значит через полгода не знать,
где что искать.

```prisma
model HomeContent {
  id               Int    @id @default(1)
  heroTitle        String @default("")
  heroText         String @default("")
  deliveryTitle    String @default("")
  deliveryText     String @default("")
  deliveryFeatures String @default("")

  @@map("home_content")
}
```

`deliveryFeatures` — одно текстовое поле, **строка = пункт**. При рендере
`split("\n")`, `trim`, отбрасывание пустых строк. Так пунктов может быть три,
четыре или ноль без миграций и правок кода.

**Чтение и дефолты.** Новый `lib/home-content.ts` держит константы с нынешними
текстами и функцию `getHomeContent()`. Правило подстановки разное для текстов и
для списка, и это осознанно:

- **заголовки и абзацы** — пустое значение заменяется константой: пустой `h1`
  ломает и вёрстку, и SEO, так что «пусто» здесь трактуется как «не задано»;
- **пункты доставки** — пустое значение означает «списка нет», галочки просто не
  рендерятся. Владелец должен иметь возможность убрать список целиком.

Если строки в БД нет вовсе (свежая база без сида), возвращаются все константы,
включая пункты. `prisma/seed.js` дополнительно заполняет строку теми же
значениями (идемпотентно, как он уже делает для `SiteSettings`).

**Поток данных.** `app/page.tsx` (серверный, уже `force-dynamic`) вызывает
`getHomeContent()` и передаёт значения пропсами. `HeroBanner` и `DeliveryBanner`
становятся «глупыми»: получают готовый текст и массив пунктов, о БД не знают.
`HeroBanner` остаётся клиентским из-за модалки — пропсы от серверного родителя
этому не мешают.

**API.** `/api/home-content` по образцу
[app/api/site-settings/route.ts](../../../app/api/site-settings/route.ts): `GET` публичный, `PATCH` только
с сессией (`auth()`), частичное обновление переданных полей, `ensureHomeContent()`
создаёт строку при первом обращении, невалидный JSON → 400, ошибка БД → 500 с
логом.

**Админка.** Новый пункт `NAV` «Главная» → страница `/admin/home` по образцу
[app/admin/(dashboard)/company/page.tsx](<../../../app/admin/(dashboard)/company/page.tsx>): загрузка через `GET`, две группы
полей («Главный баннер», «Баннер доставки»), для пунктов — `textarea` с подсказкой
«по одному пункту на строку», одна кнопка сохранения, сообщения об успехе и ошибке.

### Часть 2. Логотип и favicon — поля в `SiteSettings`

Логотип стоит в шапке **всех** страниц и логически принадлежит айдентике рядом с
`siteName`, поэтому оба поля добавляются в `SiteSettings`, а не в `HomeContent`:

```prisma
logo    String @default("")   // публичный путь /uploads/...
favicon String @default("")
```

Редактирование — на существующей странице «Данные компании», рядом с названием
сайта.

**Загрузка.** Новый роут `/api/site-settings/images`: `POST` с
`multipart/form-data`, где `field` = `logo` | `favicon`, `file` — картинка;
`DELETE ?field=logo` очищает значение. Валидация существующим
[lib/save-public-upload.ts](../../../lib/save-public-upload.ts) (5 МБ, случайное имя файла), `auth()`
обязателен. Один роут на два поля: логика идентична, различается только колонка.

**Формат favicon.** `savePublicUpload` и MIME-таблица в
[app/api/files/[file]/route.ts](<../../../app/api/files/[file]/route.ts>) расширяются на `.ico`
(`image/x-icon`, `image/vnd.microsoft.icon`) — иначе привычный `favicon.ico` не
загрузить. Подсказка в форме: «PNG или SVG, квадрат, от 64×64».

**Подключение favicon.** Сейчас `app/favicon.ico` подхватывается файловой
конвенцией Next и сам вставляет `<link rel="icon">`. Свой тег через
`metadata.icons` дал бы два конкурирующих тега в `<head>`. Поэтому файл
переезжает в `public/favicon-default.ico`, а `generateMetadata` в
[app/layout.tsx](../../../app/layout.tsx) всегда задаёт `icons`: загруженный favicon либо дефолтный
путь. Один тег, предсказуемое поведение. Семантику `metadata.icons` в этой версии
Next проверить по `node_modules/next/dist/docs/` перед правкой (требование
AGENTS.md).

**Логотип в шапке.** Внутри `<Link href="/">` в `app/layout.tsx` — нативный `img`
32×32 (`size-8 rounded object-cover`, `gap-2` до названия), с eslint-disable для
`no-img-element`, как принято в проекте. Пустой `logo` → рендерится только
название, то есть текущее поведение.

**Кеш.** Файлы отдаются с `Cache-Control: immutable`, но каждая загрузка получает
новое случайное имя — старый favicon в браузере не залипнет.

**Старые файлы на диске** при замене картинки не удаляются. Сознательно:
удаление файла по пути из БД — лишний риск, вес картинок ничтожен, и так же
ведёт себя загрузка иконок соцсетей.

## Миграции

Одна миграция Prisma: создание `home_content` и две колонки в `site_settings`.
Применяется автоматически при старте контейнера (`prisma migrate deploy` в CMD
образа), отдельных действий на сервере не требует.

## Проверка

Тексты:

- правка заголовка в `/admin/home` → виден на главной после перезагрузки;
- очистка заголовка или абзаца → показывается дефолт из `lib/home-content.ts`;
- удаление всех строк в пунктах → список исчезает, вёрстка баннера не ломается;
- четыре строки в пунктах → четыре галочки;
- `PATCH /api/home-content` без сессии → 401.

Айдентика:

- загрузка логотипа → квадрат в шапке на главной и в карточке товара;
- удаление логотипа → шапка вернулась к тексту;
- загрузка favicon → в `<head>` ровно один `<link rel="icon">` с новым путём;
- файл 6 МБ → ошибка «Файл больше 5 МБ»;
- `POST /api/site-settings/images` без сессии → 401.
